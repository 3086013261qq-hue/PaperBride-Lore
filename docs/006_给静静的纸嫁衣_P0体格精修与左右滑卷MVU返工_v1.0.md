## 二、本轮新增目标 B｜MVU 篇章页改回成熟左右滑卷结构

### 1. 交互方式
九卷只显示一个主视觉轮播卡：
- 手机：左右 Swipe；
- 桌面：鼠标/触控笔拖动；
- 同时保留“上一卷 / 下一卷”按钮；
- 键盘左右方向键可切预览，Home/End 到首末卷；
- Tab 必须正常遍历按钮，不做键盘陷阱。

### 2. 最重要的业务边界
**滑动只预览，绝不切卷。**

Swipe / 拖动 / 箭头 / 点位只允许改变 MVU 本地 `previewId`：
- 不改世界书 `enabled`；
- 不改 `ACTIVE`；
- 不改 `currentDate`；
- 不写 `MAIN_DATE_REBASE`；
- 不推进事件；
- 不生成第二套 `current_volume` 状态。

只有玩家明确点击 `进入此卷 / 开始新篇章` 才调用现有 `controller.enter(id)`，继续沿用原子切卷：
`关闭其他MAIN → 开启目标MAIN → ACTIVE同步 → 必要时日期重排 → DATE_LOCK`。

### 3. 视觉结构
废弃九宫格、双列九卷缩略卡墙、大米黄色说明框、大型“当前篇章”竖牌。

保留并强化：
- 官方 `illustrations/` 九张主视觉；
- 单张 16:9 左右宽幅主视觉；
- 底部轻遮罩卷名；
- 小型朱砂“当前”印章；
- 下方九个小位置点；
- 极简预览信息：卷名、默认起点、是否当前卷、确认按钮。

必须读取 `mvu/media-manifest.v1.json` 的 `objectPosition`，不得裁掉人物脸、杜言她大型白色蝴蝶结、奚月遥红色发带、王娇彤星形发夹等识别点。

## 三、005 的全局音乐规则继续有效，而且源码必须真正实现

旧 `assembly/src/ui.js` 存在与 005 文档冲突的实现：切换“九卷篇章 / 灯下余音”时会调用 `stopMusic()`，导致 iframe 被销毁。

006 源码已改为：
- 首次进入灯下余音时只 `attach` 一次；
- 切回篇章页只隐藏音乐控制层，不 dispose、不清 iframe；
- 再回音乐页复用同一实例；
- 合上婚书面板也不停止；
- 新 AI 楼层出现时，不因重挂 MVU 主节点而主动销毁音乐；
- `CHAT_CHANGED` 或整个 MVU `dispose` 时才释放；
- 用户主动换歌时仍由音乐模块维持最多一个活动 iframe。

## 四、005 两个构建链遗留必须在本轮一并堵死

检查当前 `assembly/build.py` 可见两个旧逻辑仍会让重建结果回退。静静必须先修构建脚本，再产候选：

### 1. 系列梗必须真正摄取
当前 build 只遍历 `characters/`、`folklore/cards/`、`locations/cards/` 与 timeline，尚未摄取 `worldbook/系列梗与彩蛋_v1.md`。

必须新增解析：
- 从该文件提取 5 个 `<核心设定:系列梗·...>...</核心设定:...>`；
- 从每个条目内部 `召回关键词:` 读取逗号分隔关键词；
- `constant=false`、`selective=true`；
- 加入 source inventory 与计数/QA；
- 最终 JSON 必须能搜到 `系列梗·纸电锯`、`系列梗·六葬菩萨掉头`；
- `纸电锯` 的 MAIN09 剧透边界保留正文原样，不做全局常驻。

### 2. 10/10 音乐验证不得被 build.py 降级
当前 build 会把所有曲目先改成 `PENDING/VERIFIED_METADATA`，又仅将 `slot != 10` 改为 `VERIFIED`，导致 slot10《芊芊》在重建时不是 `VERIFIED`；随后还把 `musicStatus` 回写成 `PARTIAL_VERIFICATION_BLOCKED`。这与权威 manifest 当前 `VERIFIED_10_OF_10` 冲突。

必须改为：
- 10 个 `detail-<id>.json` 证据全部核对 ID 后均保持/写成 `verify=VERIFIED`；
- `verifiedCount=10`；
- `musicStatus=VERIFIED_10_OF_10`；
- 不删除现有署名 discrepancy note；
- 最终 UI 的《芊芊》必须拿到有效 `track_id=102138`，不能因构建降级变成不可播。

同时更新候选卡 `creator_notes`，删除“音乐未全验，不标正式封版”这种已经过期的说明。
